# מערך סוכנים פיננסי — תכנית אב

> מסמך תכנון (אוגוסט 2026). נכתב אחרי מיפוי שלושת הפרויקטים הקיימים:
> `investment-research-rag`, `stock2growth`, ו-world-cup-app (שממנו נלמדו דפוסי
> ה-cron/עמידות). היעד: מערך חשיבה כולל של השקעות, ניהול תיק וסיכונים, מבוסס על
> ה-RAG הקיים, עם מחקר מתמשך ואגירת ידע על מניות לאורך זמן.

---

## 1. מה כבר קיים (הממצא המרכזי: יותר ממה שחשבנו)

### investment-research-rag (Python + Supabase pgvector + Streamlit)

זה כבר לא "רק RAG על ספרים" — זו מערכת מחקר כמעט שלמה:

| רכיב | קובץ | מה הוא עושה |
|---|---|---|
| ספריית ידע | `chunks`/`sources` + pgvector | ספרים, מכתבי באפט/דיימון/בזוס, מזכרי Howard Marks, FOMC, RSS חדשות, דיווחי SEC (10-K/10-Q/8-K/20-F), 13F, ויקיפדיה, חברות ת"א |
| GraphRAG | `entities`/`relationships` + `graph_retrieval.py` | גרף ידע של מושגים/אנשים/חברות עם ראיות פר-chunk |
| סוכן יחיד | `src/agent.py` | לולאת tool-use ידנית עם prompt caching; כלים: ספרייה, מחירים חיים, מדדי ביצוע/סיכון, מאקרו (FRED), דיווחים, פונדמנטלס (FMP) |
| **מחלקת מחקר רב-סוכנית** | `src/research_dept.py` | 5 מומחים (פונדמנטלי, מאקרו, קוואנט/סיכון, תזה, חדשות/בנקים מרכזיים) → סינתזת CIO בעברית |
| דוח יומי | `scripts/daily_report.py` | Market Trends יומי → קובץ Markdown מקומי (Task Scheduler בווינדוס) |
| רענון שבועי | `scripts/refresh_all.py` | ingesters עם dedup לפי hash — FOMC, Marks, ברקשייר, RSS, filings |
| UI | `app.py` (Streamlit) | צ'אט, סוכנים, גרף, שוק חי, מאקרו, פונדמנטלס; פרוס ב-Streamlit Cloud |

### stock2growth (React + Neon + Clerk + Vercel)

פלטפורמת תיקים קהילתית **חיה בפרודקשן**: תיקי מניות ו-ETF אמיתיים (מנורמלים
ל-₪100K), יומן פעולות מנומק, watchlist עם זיהוי יעדים, מחירים יומיים
(Twelve Data + בנק ישראל FX), התראות, ודפי מחקר/תוכן.

### world-cup-app — הלקחים המתודולוגיים

לא קשור פיננסית, אבל ממנו נלמדו הדפוסים שיחזרו כאן: cron אידמפוטנטי, ריפוי-עצמי
(re-score כל ריצה), הצלבת מקורות (ESPN מול football-data), הקפאת נתונים סופיים,
ואימות רחב לפני סגירת תיקון.

## 2. הפער מול החזון

החזון: "מערך חשיבה כולל של השקעות, ניהול השקעות וסיכונים... בדיקה של מניות
ואגירת המידע והמחקר עליהן באופן מתמשך."

מה שחסר, לפי סדר חשיבות:

1. **זיכרון מחקר מתמשך.** דוחות מחלקת המחקר נכתבים לקבצים מקומיים ונעלמים.
   אין "תיק חברה" (dossier) שמצטבר: תזה, דוחות קודמים, מחיר בזמן הדוח, מה
   השתנה מאז. הסוכנים מתחילים כל ניתוח מאפס.
2. **הסוכנים עיוורים לתיק.** מחלקת המחקר מנתחת חברה בודדת לפי דרישה. אף סוכן
   לא רואה את התיק האמיתי ב-stock2growth — אין ניתוח חשיפות, ריכוזיות,
   קורלציות, או בדיקת "האם התזה של החזקה X עדיין תקפה".
3. **הכול רץ מקומית בווינדוס.** Task Scheduler + קבצי bat — אם המחשב כבוי אין
   דוח ואין רענון. "מתמשך" דורש ענן.
4. **אין דחיפה יזומה.** הדוחות מחכים שתפתח את האפליקציה. אין טלגרם/מייל.
5. **אין טריגרים מבוססי-אירוע.** דיווח 8-K חדש, תנועת מחיר חריגה, פרסום דוחות —
   כלום לא מפעיל מחקר אוטומטית.

```
                    ┌────────────────────────────────────────┐
                    │        GitHub Actions (ענן, חינם)       │

                    │  אירוע: filing חדש / תנועה חריגה → מחקר │
                    └───────────────┬────────────────────────┘
                                    │ מריץ את הקוד הקיים
                                    ▼
   ┌───────────────────────────────────────────────────────────┐
   │              investment-research-rag (Python)              │
   │                                                            │
   │  מחלקת המחקר (קיימת)          סוכנים חדשים                │

   │  + הדוחות עצמם מוטמעים חזרה כ-chunks (source_type=        │
   │  'research_report') → הסוכנים הבאים רואים מחקר קודם        │
   └───────┬───────────────────────────────┬───────────────────┘
```

### עקרונות עיצוב

- **הרחבה, לא בנייה מחדש.** `research_dept.py` + `agent.py` הם הבסיס; מוסיפים
  מומחים, כלים וזיכרון — לא פריימוורק חדש.
- **הלולאה המרכבת (compounding loop):** כל דוח שנוצר נשמר ב-DB **וגם** מוטמע
  חזרה לספריית ה-RAG. מחקר על NVDA בעוד חודש יתחיל ממה שנכתב עליה החודש —
  זו "אגירת המידע" מהחזון, וזה מה שהופך את המערכת לחכמה יותר עם הזמן.
- **עוזר מחקר מפוקח, לא מקבל החלטות.** בהתאם לספרות (CFA Institute 2026):
  המערכת ממליצה, מתריעה ומנמקת; ההחלטות שלך. כל דוח נושא disclaimer.
- **תקציב חינם:** GitHub Actions (חינם לפרטי עד 2,000 דק'/חודש — נשתמש
  בעשרות), Telegram Bot API (חינם), Supabase free, מקורות keyless (EDGAR,
  FRED, RSS, yfinance). עלות ה-API של Claude נשלטת עם תקרה פר-ריצה
  (כבר יש מדידת עלות ב-`agent.py`).

## 4. שלבי ביצוע

### שלב 1 — זיכרון מחקר (התשתית של הכול)

מיגרציה ב-Supabase של ה-RAG:

```sql
companies         -- ticker, שם, שוק (US/TASE), סטטוס מעקב (holding/watchlist/researched)
research_reports  -- company_id, סוג (deep/update/portfolio_review/daily),
                  -- תוכן MD, עמדות המומחים (stances JSONB), מחיר בזמן הדוח, עלות, מודל
theses            -- תזה חיה פר חברה: טקסט, סטטוס (intact/eroding/broken), עדכון אחרון
signals           -- אירועים שנצפו: filing חדש, תנועת מחיר, חציית יעד, שינוי מאקרו
```

שינויים בקוד:
- `run_department()` שומר את התוצאה ל-`research_reports` (במקום/בנוסף לקובץ).
- ingester קטן שמטמיע דוחות שנשמרו כ-chunks עם `source_type='research_report'`.
- כלי חדש לסוכנים: `get_research_history(ticker)` — דוחות ותזות קודמים.

**תוצר:** מחקר שמצטבר. אפשר לשאול "מה חשבנו על X לפני חודשיים ומה השתנה".

### שלב 2 — סוכני תיק וסיכונים

- כלי `get_portfolio` — קריאה בלבד מ-Neon של stock2growth (connection string
  ב-secrets; לחלופין endpoint קיים). מחזיר החזקות, משקולות, מזומן, watchlist.
- מומחה **מנהל תיק**: הקצאה מול יעדים, ריכוזיות (פוזיציה/סקטור/מטבע),
  מה מועמד לחיזוק/קיצוץ — מנומק מהספרייה (Buffett על ריכוז, Marks על מחזורים).
- מומחה **מנהל סיכונים**: משתמש ב-`analytics.py` הקיים — beta/קורלציה של כל
  החזקה מול התיק, volatility תיק, תרחישי לחץ פשוטים (ריבית, מלחמה, טק).
- מצב ריצה חדש `run_portfolio_review()`: שני המומחים החדשים + מאקרו + CIO,
  על התיק כולו במקום חברה בודדת.

**תוצר:** סקירת תיק מלאה בפקודה אחת, עם עמדות מנומקות פר החזקה.

### שלב 3 — הלולאה האוטונומית בענן

GitHub Actions ברפו של ה-RAG (הסודות עוברים ל-GitHub Secrets):

| Workflow | תדירות | מה רץ |
|---|---|---|
| `daily-brief` | ימי מסחר, בוקר ישראל | רענון RSS/מחירים → daily_report → טלגרם/מייל |
| `monitor` | ימי מסחר, כל שעתיים בשעות מסחר | signals: תנועות > 4%, filings חדשים להחזקות/watchlist, חציית יעדי watchlist → התראה + תיוג ל-queue מחקר |
| `weekly-research` | סופ"ש | refresh_all מלא → מחקר עומק לתור (חברה-שתיים בתקציב) → סקירת תיק שבועית |

עקרונות מ-world-cup-app: כל job אידמפוטנטי, dedup לפי hash/מפתח, try/catch
פר-שלב כך שכשל אחד לא מפיל את השאר, ותקרת עלות $ פר ריצה (נמדדת ממילא).

**תוצר:** המערכת חיה גם כשהמחשב כבוי; "מתמשך" באמת.

### שלב 4 — ממשקים

- **טלגרם (ראשון):** בוט אישי — דוח בוקר, התראות signals, סקירה שבועית.
  בהמשך גם פקודות (`/research NVDA`, `/portfolio`) דרך polling ב-Actions או
  webhook קטן.
- **מייל:** Resend free tier (100/יום) לסיכום השבועי המעוצב.
- **Streamlit (קיים):** טאב "היסטוריית מחקר" — דוחות מה-DB, ציר זמן תזה פר חברה.
- **אופציונלי בהמשך:** MCP server דק מעל אותם כלים — צ'אט עם המערכת ישירות
  מ-Claude; והצגת דוחות נבחרים ב-ResearchPage של stock2growth.

## 5. החלטות פתוחות (עם המלצות)

| החלטה | המלצה | נימוק |
|---|---|---|
| היכן רצה הלולאה | **GitHub Actions** | חינם, מריץ את הפייתון הקיים בלי porting (Supabase Edge = Deno = לשכתב הכול) |
| ערוץ דחיפה ראשון | **טלגרם** | חינם, מיידי, תומך Markdown, קל להוסיף פקודות בהמשך |
| חיבור לתיק | **קריאה בלבד מ-Neon** | הסוכנים לא כותבים לתיק לעולם; stock2growth נשאר מקור האמת |
| היכן חי הקוד | **בתוך investment-research-rag** | שם הסוכנים, הכלים וה-DB; מסמך התכנון הזה יועתק לשם בתחילת הביצוע |
| סדר שלבים | **1 → 2 → 3 → 4** | הזיכרון קודם — בלעדיו הסוכנים החדשים והלולאה מייצרים דוחות שנעלמים |

## 6. עלויות צפויות

- תשתית: ₪0 (GitHub Actions, Telegram, Supabase/Neon free, מקורות keyless).
- Claude API: דוח יומי ~$0.05–0.15; מחקר עומק ~$0.5–1.5; סקירת תיק ~$1–2.
  קצב מלא ≈ **$15–30/חודש**, נשלט בתקרות פר-ריצה. אפשר להוזיל עם Haiku
  לניטור ו-Sonnet/Opus רק לעומק.
